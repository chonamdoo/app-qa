# QAutra 재설계 · Space 화면 참고 기준

기준 문서: [제품 재설계 · Open Design 전달 문서](../../plans/2026-11-01-qautra-product-design-brief.md).

## 범위와 근거

[inferred] 이번 작업은 제품 코드 구현이 아니라 Mac QA 앱의 화면·상태·사용 흐름 설계다. 실제 엔진·VM·기기·권한 설정은 변경하지 않는다. 클릭 가능한 웹 프로토타입으로 화면을 검토하고 네이티브 통합은 별도 검증한다.

[measured] Space 참고는 사용자가 이 대화에 제공한 Ego 화면 캡처다. 마지막 캡처는 1568×851 이미지이며 두 작업 카드와 추가 영역, 선택 테두리, 아래쪽 단축키 안내가 보인다. 이미지 크기는 앱의 CSS viewport나 실제 화면 배율을 뜻하지 않는다. 첨부 원본은 현재 대화의 근거이며 이 Markdown에 이미지 파일이 동봉됐다는 뜻은 아니다.

[measured] 시각 기반은 `/Users/namdoo/Downloads/qautra-design-package.zip`의 `COMPONENTS.md`, `design-tokens.json`, `ui/components.css`다. 기존 패키지는 밝은 QAutra shell과 공통 컴포넌트를 제공하며 실제 QA 엔진에 연결되지 않은 프로토타입이라고 명시한다.

## Ego Space에서 가져올 여섯 가지 메커니즘

1. [measured] Space 목록은 작업 화면의 미리보기를 앞세운다. 사용자가 준 캡처에는 두 개의 작업 미리보기와 별도의 추가 영역이 한 줄에 보인다. VM CPU·디스크 수치가 화면의 중심이 아니다.
2. [measured] 작업 이름은 미리보기 아래에 붙어 있다. 화면 내용과 작업 식별을 함께 훑을 수 있으며, 제목을 원시 실행 ID만으로 표시하지 않는다.
3. [measured] 선택된 Space는 다른 카드와 구별되는 테두리를 가진다. 선택 표시와 실행 상태는 다른 정보다. 색상만으로 상태를 전달하지 않는 추가 표시가 필요하다.
4. [measured] 앞서 제공한 실행 중 캡처에는 카드 아래 `Running` 표시가 있다. 실행 중 여부와 선택 여부를 따로 전달하는 구조를 참고한다. 정지 이미지로 상태 전이·갱신 주기·녹화 여부는 알 수 없다.
5. [derived] 미리보기 중심 카드 구조는 작업 전환의 진입점으로 사용할 수 있다. QAutra에서는 카드를 눌러 실행 상세의 관측 모드로 들어가되, 카드 수를 실제 브라우저/VM 동시 실행 수로 해석하지 않는다.
6. [measured] 목록 하단에는 Space 전환 단축키 안내가 있다. QAutra도 키보드로 작업 목록·상세·결과를 이동할 수 있어야 한다. Ego의 단축키 조합 자체를 그대로 복제해야 한다는 뜻은 아니다.

## 적용 경계

[inferred] Ego의 어두운 외관을 복제하지 않는다. 최종 설계 문서가 지정한 QAutra의 밝은 shell·기존 아이콘·navigation을 유지하고, 작업 화면 중심의 Space 전환 방식을 가져온다.

[inferred] QAutra의 Space 카드는 선택한 실행에 속한 논리 작업 화면이다. 사용자가 `+`를 눌러 매번 VM을 만들게 하지 않는다. 기본 시작점은 `시나리오 가져오기`와 `새 실행`이다.

[inferred] 자동 실행 화면은 관측이 기본이다. 호스트 포인터·키보드·포커스를 사용하지 않는 요구는 필수 실행 계약이며 Ego 캡처만으로 검증한 사실이 아니다. 프로토타입에는 `자동 실행 · 입력은 테스트 환경 내부로만 전달`이라는 요구 안내와 `디자인 예시 · 실제 연결 없음` 표시를 함께 둔다. 확인하지 않은 비간섭을 초록색 인증 배지로 만들지 않는다.

[inferred] 이미지에 없는 모션·전환 속도·실제 쿠키 격리·OS 격리·호스트 비간섭·처리량은 추론해 측정값처럼 쓰지 않는다. 화면 크기와 공통 토큰은 QAutra 원본 소스와 최종 문서에서 정한다.

## 검수 크기와 원본의 반응형 조건

[measured] 최종 설계 문서 §13은 1024×768, 1440×900, 1920×1080 CSS px를 디자인 검수 크기로 제안한다. 지원 하드웨어나 실제 앱 최소 창 크기의 확정값은 아니다.

[measured] 원본 `ui/components.css`의 media query 경계는 1400/1100/900/767/479px다. 기본 sidebar는 token 228px이고 1100px 이하에서 196px, 767px 이하에서 64px, 479px 이하에서 56px로 바뀐다. 새 화면의 결과는 실제 렌더 뒤 판단한다.

[inferred] 웹 프로토타입은 `floor.web.md`의 접근성·overflow·상태 기준을 적용한다. Mac 네이티브 통합은 시스템 초점·VoiceOver·실제 창 종료·권한 흐름을 별도로 검증한다. iOS/Android 전용 tab bar/FAB 규칙을 Mac 관리 앱의 구조로 가져오지 않는다.
