# QAutra architecture contract

`references/design.md` is the full design (numbers, rules, measured evidence). This file is the normative summary reviewers check. When the two disagree, fix the disagreement; do not pick one silently.

## Roles

- **Code** owns rules, permissions, scheduling, execution, and verdicts. Ordinary QA submits scenarios and reads results without operating an AI agent.
- **Jev** answers narrow typed questions in legacy DSL execution and generation review. Published deterministic regression execution does not require runtime model calls; its authority is defined in §14.
- **AI caller** may submit interpretation, code, or analysis drafts through the shared CLI/MCP/SDK contracts. It cannot authorize effects, choose parallel execution, change a published definition, or declare PASS.
- **Planner LLM** optionally generates draft tests from documents in `qa plan`, read-only, no tools.
- **Humans** review source interpretation and executable scope; environment owners provision project grants separately from scenario publication.

## Modules and allowed dependencies

| Module | Path | May import |
|---|---|---|
| contracts | `src/core/*` (incl. the platform table `src/core/platform.ts`), `src/spec/{schema,load}.ts` (DSL schema, `stepLabel`, the static checkEach rule check) | node builtins, `zod`, `yaml`, other contracts — no other `src/` module |
| observe | `src/observe/*`, `src/ocr/*` | contracts |
| policy | `src/policy/*` (deterministic risk policy and project-grant decisions; it may read trusted grant files but never writes, spawns processes or uses the network — grant-scoped fixture clients live in the runner) | contracts, `src/observe/text.ts` |
| jev | `src/jev/*` | contracts; `observe` and `policy` only from calibration code (`src/jev/calibrate.ts`) |
| drivers | `src/appium/*`, `src/drivers/*` | contracts, observe parsers (`src/observe/{android,ios,web}.ts`) |
| runner | `src/runner/*`, `src/report/*` | contracts, observe, ocr, policy, jev; `src/drivers` only from the runner entry (`src/runner/index.ts`) — execution code consumes the `Driver` interface |
| plan | `src/plan/*` | contracts, observe, policy, jev; the runner entry only for `--run` |
| server | `src/server/*` | contracts; runner/plan/drivers only through injected handlers |
| CLI (composition root) | `bin/qa.ts`, `src/cli/**` | anything; each command loads its module lazily |
| mac app | `mac/**` | the `qa serve` HTTP/SSE API and `.qa/server.json` (port, bearer token); it launches the engine, owns the operator review secret and hands it to the engine only as the first stdin line (never on disk or in the environment); it may write its own child-output log `.qa/logs/engine.log` and its own durable submission intents under `~/Library/Application Support/QAutra/` (0600, file and directory entries fsynced, rename) so a lost reply is looked up by the same request UUID instead of resubmitted. One file protocol with the engine: for an authorized native evidence download the engine creates a lease directory `~/Library/Application Support/QAutra/product-evidence/native-downloads/<id>/` (0700) with `lease.json` and an empty reserved `payload.tar` (0600), and later may add `retired.json` (revocation fence) and `closed.json` (acknowledged cleanup); the app reads those engine records, fills `payload.tar` from the authorized export download (exact size and SHA-256, fsync), saves it to the destination the user picks in a save panel, then removes it, and writes its own `local-save.json` and `cleanup.json` there (0600 temporary file, fsync, rename); the engine reads `cleanup.json` back. At most four leases may await confirmed cleanup (a fifth reservation is 507 `native_download_limit`), and an unreadable, unparsable or orphaned lease record blocks reservations with 409 `native_download_cleanup_required`. Beyond these the app writes evidence only to a transient playback copy of a hash-verified video segment in its temporary directory (0700/0600) that it removes when the player disappears |

No import cycles between modules, and no module imports the CLI. The Jev candidate row format is a contract (`src/core/candidate-row.ts`). A contract change (`src/core/*`, `src/spec/*`, events) updates every consumer in the same change. `test/architecture/` enforces this table.

Apps and websites share one pipeline (definition, runner, policy, preparation, sanitizer, and reports). Targets, drivers and observation parsers differ; ordinary QA uses a published regression definition (§14), while legacy DSL and B02 direct execution retain their narrower authorization contracts. Every platform list and label derives from `PLATFORM_INFO`; a platform switch is exhaustive, never "not android ⇒ iOS".

## Invariants (must)

1. **Fail-closed verdicts.** PASS only from a deterministic check or a calibrated Jev gate. Missing, malformed, uncalibrated, timed-out, or ambiguous answers are ERROR or INCONCLUSIVE, never PASS. A rule that evaluates nothing (e.g. an empty or multi-operator JSONLogic object, a missing operand, a collection operator over a non-array) is ERROR; a line missing a variable the rule reads is never evaluated (INCONCLUSIVE). Verdict precedence ERROR > FAIL > INCONCLUSIVE > PASS.
2. **Jev contract.** Model pinned (`jev-1.13.0`) and checked on every response; strict answer validation (own-property membership, exact key sets, finite probabilities) before use; thresholds come only from `calibration/<model>/<questionVersion>.json`; no coordinates in state; redaction before any text leaves the machine; ≤ 254 candidates + `none` (overflow is flagged, never truncated).
3. **Actions.** Every mutating action is journaled (fsync) before dispatch. Transport failure, timeout, or an unvalidated driver response → `uncertain` → test ERROR, never retried and never reclassified as `completed`/`rejected`. No-effect after an action → INCONCLUSIVE unless `expectNoChange`.
4. **Risk.** The deterministic policy (`src/policy`: Korean/English keywords, destructive-dialog context, unlabeled targets) runs on the **final fresh target and screen** immediately before dispatch, including `press: enter` and `type.submit`. In legacy DSL execution, the Jev commit check can only add refusals and is required for every target-based mutation of a deterministically safe target without `allowRisky` (tap, long press, type/clear, submit/enter); after its answer the screen is observed again: the target must be the same node (tree path and resource id; on desktop web the same DOM element) with the same box and state (`stale_target` otherwise), and the action's effect is measured from that observation and the deterministic policy runs again on that observation (a destructive dialog that appeared meanwhile blocks); unrelated screen changes (clocks, live counters) do not void the approval. Its gate is per surface (`commit.gate` for apps, `commit.surfaceGates.web` for websites, recorded only after a holdout confirms it); an error, a gate that is not `calibrated`, or a surface without its own gate is ERROR `commit_check_unavailable` and nothing is dispatched. Risky targets act only with `allowRisky` and only through selector/fast path. On web targets, `open` outside the profile origins is refused whatever `allowRisky` says.
5. **Observation.** Only touchable nodes occlude; taps use the fresh un-occluded tap point after `refind` + hit-test (iOS WDA `hittable` of the target's own box, desktop `elementFromPoint`); settle means change → stable on identity/layout fingerprints; an observation cut by a depth or node cap never yields an absence PASS, a `checkEach` PASS or an approved target-based mutation (INCONCLUSIVE `observation_truncated`); a target that is not stable within the post-scroll window is `stale_target`, not tapped. On device browsers the browser UI (address bar, toolbars, snackbars, the iOS status-bar strip) is never a candidate but still occludes. Page scripts only observe (DOM extract, value read-back, `elementFromPoint`, `history.length`, `location`) — actions are real pointer/key input, never JS clicks, DOM value injection or forced clicks. The only exceptions are project-fixture bootstrap under a current grant (§14): installing the grant's host-only, `httpOnly`, `SameSite=Strict` fixture cookie through WebDriver on the granted origin, and a bounded credentialed `GET` of the grant's witness URL (at bootstrap and again before each dispatch, so every mutation runs on a fresh client proof) from a document on that origin, checked in the same script; neither touches page elements, and both are refused outside the granted origins.
6. **Devices and input isolation (§14).** Every execution resource is reached through `Driver` and held exclusively for the declared flow. Chrome uses an owned automation context/profile; real Safari uses a prepared macOS worker's actual Safari automation session and any required worker desktop. Neither may raise or inject global input into the user's host desktop, reuse a personal browser profile, or substitute WebKit for Safari. A Space observes an attempt; it does not imply a new VM or OS installation per test. The input boundary must be verified through preparation, dispatch, cleanup and failure, not inferred from a capability flag; until measured, records state it as inferred, never as verified. Device/context/process/worker ownership and unknown-outcome fences survive until confirmed cleanup. Tools remain project-local, except `ffmpeg`/`ffprobe`, which are resolved once per recording from the engine `PATH` (then `/opt/homebrew/bin`, `/usr/local/bin`) to one absolute executable used for both capture and validation; failure diagnostics name the resolved paths. Appium startup remains single-flight per owned port, app ids and URLs remain validated, device-shell arguments remain quoted, browser setup remains explicit, and only owned `adb reverse` mappings may be removed.
7. **Evidence.** Directories 0700, files 0600. Every journal/event/SSE/source/elements/log write passes one sanitizer that masks observed `secure-input` values (regardless of the DSL `secure` flag), `${ENV}`-expanded values, app-profile `redact` matches and sensitive URL query values; typed text never appears in step labels; records written outside a test session (skips, smoke start) pass it too; Appium never logs request bodies; events follow `src/core/events.ts` and name the DSL action exactly. Readiness failures (browser not prepared, page never shows content) are ERROR (`qaStatus` BLOCKED), never FAIL or PASS.
8. **Generated tests** are validated deterministically (zod, coverage, no `allowRisky`, no risky labels, no submit/enter), reviewed per criterion (no aggregate score), and saved as `draft` unless explicitly approved.
9. **Durable records** (calibration, `plan.json`, generated tests, `summary.json`, `.qa/server.json`) are written atomically; regenerating a plan never removes existing tests before the new generation is complete.
10. **Direct scoped execution (§13).** A trusted project grant for a product-owned synthetic fixture, explicit device, screenshot capture and allowed action kinds replaces mandatory model checks only in the direct session path. Deterministic risk, exact session/revision/ref identity, final freshness/hit-test, shared journal/sanitizer/settle/health and unknown-outcome ownership remain mandatory. Coordinates need an additional fresh-frame capability and never override destructive-screen risk. Client input cannot grant authority, request global `allowRisky`, or expand worker scope; JS/TS strings stay literal. A worker completion is not business PASS, and authorized-code process isolation is not a malicious-code sandbox.
11. **Published regressions (§14).** A reviewed, content-frozen definition binds source interpretation, required checks, targets and dependencies. A separate trusted project grant binds environment/tenant/account, operations, owned fixture/entities, effects/sinks, expiry and policy version; publication and client input never create that grant. Each dispatch rechecks authority, deterministic risk and target freshness through the common execution pipeline. Unsupported model-dependent checks are rejected before publication rather than weakened. Scheduling is code-owned, defaults to one active independent flow across the local user's projects and entry points, and holds admission through required evidence and cleanup. Restarted or uncertain work is reconciled, never automatically replayed. Business, execution certainty, evidence and cleanup remain separate; overall PASS requires every nonempty required scope and its mandatory video/cleanup conditions to be satisfied.

## Must avoid

- A model (Jev or LLM) deciding PASS/FAIL or granting permission on its own.
- Treating an absent or invalid model answer, or a skipped required check, as a default value.
- Retrying a mutating step, re-tapping when nothing changed, or replaying an `uncertain` action.
- Unconditional BACK to hide a keyboard; a silent no-op `back`; iOS clipboard text entry; ESC to hide a keyboard on a web page (it clears search fields).
- Global tool installs, or reading devices/Appium outside `src/drivers`.
- Execution code importing concrete drivers, servers importing runner/plan directly, or any module importing the CLI.
- Truncating candidate lists, sending coordinates or unredacted text to Jev, logging API keys, secrets, or request bodies.
- Aggregate scores that hide a failing criterion.
- JS clicks, DOM value injection or forced clicks on web targets; calling Playwright WebKit or viewport emulation "Safari" or "mobile".
- Host-global foreground, pointer, keyboard or clipboard automation as a fallback for an isolated execution resource.
- Treating a review checkbox, scenario publication, AI output or a synthetic-fixture grant as authorization for another project's data or effects.
